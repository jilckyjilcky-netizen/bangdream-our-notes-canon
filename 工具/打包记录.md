# 打包记录 · 本项目怎么打包、打出过哪些包、踩过哪些坑

> **给未来的自己看，也给要发包的人看。**
> 一句话原则：**用户说「打个包」，就直接扔 zip，别的都往后放**（见 §6）。
>
> 本文即 `工具/打包.mjs` 的配套说明文档，两者要一起改。

## 1. 最短路径

**用户说「打个包」时，只跑这一条：**

```bash
node 工具/打包.mjs
```

**用户说「打个对外的包 / 发给别人」时，跑这一条：**

```bash
node 工具/打包.mjs \
  --out "D:/Project/BanG Dream! 同人小说资料库（2026年10月版）.zip" \
  --exclude 工具 --exclude mcp-canon --exclude masterdata \
  --exclude 归档 --exclude 跑道 --exclude 模式原型 --exclude links \
  --add 归档/_打包/先看我.md
```

**双击也行**：根目录 `打包.cmd`（等价于不带参数的 `打包.mjs`），参数可跟在后面。

产物落在**上级目录** `D:\Project\`。

> ⚠️ **注意命令里没有「排除自己」**：`--exclude 工具` 也会把本文档
> （`工具/打包记录.md`）排除掉。这是对的 —— 打包脚本的使用说明不给收包的人看。
> 但也意味着**这份文档永远不会出现在自己打的包里**，改它不会影响包内构成。

## 3. 全部参数

| 参数 | 作用 |
|---|---|
| （无） | 全量打包 → 上级目录/工作区名_时间戳.zip |
| `--dry` | 只列清单和体积，不落盘。**探口径用这个** |
| `--slim` | 去掉 `素材全量/` + `masterdata/`（775 文件 / 14.9 MB） |
| `--out <路径>` | 指定 zip 路径（给目录则放进去） |
| `--only <目录>` | 只打指定目录，可重复 |
| `--exclude <模式>` | 排除，可重复 |
| `--add <本地路径>` | 额外塞文件进 zip（**跳过全部排除规则**），可重复 |
| `--addas <zip内路径>` | 与 `--add` 按出现顺序配对，定 zip 内位置 |
| `--store` | 不压缩，快但体积大 |
| `--no-verify` | 跳过落盘后自检。**对外的包不许开** |
| `--with-secrets` | 强制含凭据文件（自己备份才用） |

## 4. 三道排除关

打包脚本按顺序过三关，任一命中就排除：

1. **隐藏规则** —— 路径任一段以 `.` 开头即跳过。
   两个例外：`.gitignore` 等点文件保留、`.workbuddy/skills/` 是项目资产带白名单放行。
   垃圾名单另有一张：`.env` `.DS_Store` `Thumbs.db` `.npmrc` `.bash_history`
   `.kb-embeddings.json`（17MB 向量缓存，可重建）。
2. **解析根 `.gitignore`** —— 直接读文件，不另抄一份清单。
   **所以以后改 `.gitignore` 就是改打包口径**，两处永远一致。
3. **凭据硬保险** —— 落盘后再扫一遍清单，命中 `交接.md` / `autodl-接入信息.md` /
   `归档/_cloud_probe.mjs` / `归档/_probe_cloud2.mjs` 直接 `exit 1`（除非 `--with-secrets`）。
   依据是 `交接.md` 原文写着「请勿提交仓库或外发」。

## 5. ⚠️ 踩过的坑（三次坏包，都是静默的）

### 坑 1：usize 传错，整包 CRC 全炸（已修）

`emit()` 签名里根本没有 usize 参数，直接拿压缩后的 `bodyBuf.length` 顶上了。
走了 deflate 的条目，头里记的「原始大小」是压缩后大小，CRC 却按原始内容算。
→ **3519/3545 个文件 CRC 不匹配，而脚本自报「完成: 9.8 MB，压缩率 70%」，一点异常都没有。**

修法：`emit()` 加 usize 参数，调用处显式传 `raw.length`；另补 `writeAll()` 循环
（`fs.writeSync` 不保证一次写完）。

**泛化教训**：自己手写的归档器，**头字段必须显式传原始长度**，绝不能让「buffer 长度」兼任。

### 坑 2：`many()` 用 `indexOf` 反查，重复参数只生效第一个（已修）

```js
// 错：argv = ['--exclude','工具','--exclude','mcp-canon','--exclude','masterdata']
argv.filter(...).map((a,i) => argv[argv.indexOf(a) + 1])
// => ["工具","工具","工具"]     ← mcp-canon 和 masterdata 被悄悄换成了「工具」
```

后果：对外包**只排除了 `工具/`**，`masterdata/`（178 条目）`归档/`（144）
`mcp-canon/`（14）`跑道/` `links/` 全打进去了 —— 而 `先看我.md` 明确叫读者跳过这些。
**包从 6.9 MB 涨到 9.4 MB，还混进了上游原始数据。**

修法：换成线性扫描按下标取值，不做任何反查：

```js
function many(name) {
  const out = [];
  for (let i = 0; i < argv.length; i++) {
    if (argv[i] !== '--' + name) continue;
    const v = argv[i + 1];
    if (v === undefined || v.startsWith('--')) continue;
    out.push(v);
  }
  return out;
}
```

**泛化教训**：凡是「重复传同一个开关」的参数解析，绝不能用 `indexOf` 反查位置。
**而且必须真的把参数逐个验一遍** —— 这个 bug 在自查时是看不出来的，
只有把产物解开、看目录构成，才知道排除到底生效没有。

### 坑 3：包被截断，连 EOCD 都没有

20:01 那个对外包 4.2 MB，尾部字节 `1aee82c3 f054f61f`，
全文件搜 zip 结尾签名 `504b0506` **零命中** → python 直接 `BadZipFile: File is not a zip file`。
不是 CRC 问题，是**整个文件没写完**。

**这条到现在没查到确证**（脚本 `verifyZip()` 里 `if (eo < 0) return {fatal}` 本该拦住，
但那个包当时自检是「通过」的 —— 怀疑是更早的旧实现打的，或当时关了 `--no-verify`）。

## 7. ✅ 交付前必须做的两道校验

**第一道**：脚本自带的 `verifyZip()`（默认全量 3311 条目 0.2s）。
它自己解析 EOCD + 中央目录，逐个 inflate 回来比 CRC，失败 `exit 1`。
**对外的包不许 `--no-verify`。**

**第二道**：**用外部工具交叉验**（脚本自述的"完成"不可信，见坑 1、坑 3）：

```bash
python -c "import zipfile;z=zipfile.ZipFile(r'<包路径>');print(z.testzip(),len(z.namelist()))"
```

`testzip()` 返回 `None` 才是好包。7-Zip / `unzip -t` 同理。

**再加一条（这次才补上的）**：解开看目录构成，确认 `--exclude` 真的生效了：

```bash
python -c "
import zipfile,collections
z=zipfile.ZipFile(r'<包路径>')
print(collections.Counter(x.split('/')[1] for x in z.namelist() if '/' in x).most_common(20))"
```

—— 这一步正是抓住坑 2 的动作。别省。
